I read all 18 files (1,277 lines). This is a Flask + SQLite ledger API. Findings below, most severe first.

## Critical

| # | Finding | Evidence | Impact | Priority | Proposed Fix | Risk |
|---|---------|----------|--------|----------|--------------|------|
| 1 | **Unauthenticated admin user export.** The legacy aliases for `/admin/users` and `/admin/audit-log` resolve through `app.view_functions[...]`, which returns the `require_role("admin")`-wrapped view. `/admin/export-users` instead passes the raw module attribute `admin.export_users` — `_protected()` wraps a *copy* at registration time and never rebinds the module name, so the alias gets the undecorated function. | `routes/__init__.py:36-41`, `routes/admin.py:39`, `routes/admin.py:18-21` | Anonymous `GET /admin/export-users` dumps every user's id, username, email, role and active flag. The module docstring at `routes/admin.py:1-6` asserts this cannot happen. | P0 | Register the alias from `app.view_functions["admin.export_users"]`, like the other two. | Low — one-line change, no contract change. `CONFIRMED` |
| 2 | **Password reset tokens are forgeable.** The token is `sha256(f"{email}:{window}")[:32]` — no secret key, no per-user entropy, no stored state. | `password_reset.py:22-24`, consumed at `password_reset.py:42` | Anyone who knows a victim's email computes the valid reset token offline and takes over the account via `POST /api/session/password-reset/confirm`. Full account takeover, including admins. | P0 | Use `hmac.new(config.SECRET_KEY, ...)` at minimum; better, store a `secrets.token_urlsafe(32)` row with a user id, expiry and single-use flag. | Medium — changes token format, invalidates in-flight reset links. `CONFIRMED` |
| 3 | **Privilege escalation via onboarding.** `complete_profile_step` builds its UPDATE from `serializers.user_fields()`, which is `USER_FIELDS` — and that tuple includes `role` and `email`. The owner-safe allowlist `WRITABLE_BY_OWNER` exists but is only used by `routes/profile.py:32`. | `routes/onboarding.py:53-63`, `serializers.py:3-12` | Any authenticated user: `POST /api/onboarding/profile {"role":"admin"}` → immediate admin. Same path sets `email` directly, bypassing the uniqueness check and `email_verified=0` reset that `routes/profile.py:62-72` enforces. | P0 | Pass `WRITABLE_BY_OWNER | {"username"}` here; drop `role` from any owner-writable set. | Low — narrows an interface that should never have been wide. `CONFIRMED` |

The worker's `_resolve` then falls back to `os.path.join(IMPORT_ROOT, path)` — and `os.path.join` with an absolute second argument discards the root entirely. | `routes/upload.py:58` (validates manifest only), `routes/upload.py:64-74`, `jobs/import_job.py:14-18` | `{"manifest":"ok.csv","entries":["/etc/passwd"]}` or `"../../etc/shadow"` makes the worker read any file the process can reach and load its contents into the caller's `contacts` rows, readable back through the API. ## High

| # | Finding | Evidence | Impact | Priority | Proposed Fix | Risk |

| 5 | **Debug mode is always on.** `DEBUG = os.environ.get("APP_DEBUG", "false")` is a *string*; the non-empty default `"false"` is truthy, and `if config.DEBUG:` never evaluates false unless the variable is set to the empty string. | `config.py:7`, `app.py:57-68` | Every unhandled 500 returns the exception message, type, full traceback and the `g.user` object to the client. Leaks SQL, file paths and session identity in production. | P1 | `DEBUG = os.environ.get("APP_DEBUG", "false").lower() in ("1","true","yes")`. | Low. `CONFIRMED` |
| 6 | **Transfers are not atomic and race on the balance check.** `create_transfer` issues four separate `db.execute` calls on a connection opened with `isolation_level=None` (autocommit) — no `db.transaction()` wrapper, unlike every other mutating path in the codebase. | `routes/transfer.py:46-67`, `db.py:22`, cf. `db.py:36-46` | Two concurrent requests both pass `balance_cents < amount` at line 46 and both debit → overdraft. A crash between lines 53 and 57 destroys money; between 57 and 62 leaves the ledger inconsistent with balances. | P1 | Wrap the whole operation in `with db.transaction() as conn:` (which already uses `BEGIN IMMEDIATE`) and make the debit conditional: `UPDATE ... WHERE id = ? AND balance_cents >= ?`, checking `rowcount`. | Medium — touches money movement; needs tests. `CONFIRMED` |
| 7 | **Reversal is replayable and only reverses one leg.** `reverse_transfer` has no guard that the ledger entry was already reversed, and it adjusts only `entry["account_id"]` — never the counterparty. | `routes/transfer.py:72-97` | A user transfers X to another account, then reverses their own debit entry (`amount_cents = -X`): `balance - (-X)` credits X back while the destination keeps X. Money is minted. With no idempotency guard the same `transfer_id` can be replayed in a loop. | P1 | Add a `reversed_at`/`reversal_of` column enforced uniquely, and reverse both legs inside one transaction. | Medium — schema change required; flag before implementing. `CONFIRMED` |

Two notes on things I checked and found **sound**: `db.build_order_clause` (`db.py:62-67`) correctly allowlists the sort column and direction, so the f-string interpolation in `routes/users.py:31` is not injectable; and `validate_import_path` (`validators.py:33-52`) is solid — per-segment regex plus a `realpath` containment check. Issue #4 is a failure to *call* it, not a flaw in it.
