## Security Audit Report — `/tmp/tmp.v3vXLCQWDK/target`

### Summary

This is a Flask-based financial ledger API (SQLite, session cookies, file imports, money transfers). The overall risk is **Critical**. The most severe findings are: a guessable password-reset token with no secret key, a privilege-escalation path via onboarding that lets any user become admin, and an unauthenticated admin data-export endpoint. Several additional high-severity issues exist in the transfer and batch-import flows.

---

### Findings

| # | Vulnerability | File:Line | CWE | Severity | Status | Fix |
|---|--------------|-----------|-----|----------|--------|-----|
| 1 | **Password reset token has no secret — fully guessable** | `password_reset.py:22–24` | CWE-640 | Critical | CONFIRMED | Derive token with HMAC-SHA256 keyed on `config.SECRET_KEY`, or generate a random token and store its hash |
| 2 | **Unauthenticated admin user export** (`/admin/export-users` bypasses `require_role`) | `routes/__init__.py:38–41` | CWE-284 | Critical | CONFIRMED | Use `app.view_functions["admin.export_users"]` (the wrapped version) instead of `admin.export_users` |
| 3 | **Privilege escalation via onboarding** (`role` field writable in profile step) | `routes/onboarding.py:53–54`, `serializers.py:6–10` | CWE-269 | Critical | CONFIRMED | Remove `"role"` (and `"email"`) from `USER_FIELDS` / `user_fields()`; use a separate admin-only allowlist |
| 4 | **Path traversal in batch import** (entry paths not validated; absolute path bypasses `IMPORT_ROOT`) | `routes/upload.py:64–75`, `jobs/import_job.py:14–18` | CWE-22 | High | CONFIRMED | Call `validate_import_path()` on each entry path and pass `resolved` in the queue message, same as the single-import endpoint |
| 5 | **Race condition / TOCTOU in money transfer** (balance check and debit not atomic) | `routes/transfer.py:46–67` | CWE-362 | High | CONFIRMED | Wrap the balance read, check, and both updates in a single `db.transaction()` block; use `SELECT … WHERE balance_cents >= ?` inside the UPDATE instead of a separate read |
| 6 | **Reverse transfer allows infinite balance inflation** (no idempotency; reversing a negative ledger entry adds money) | `routes/transfer.py:72–97` | CWE-840 | High | CONFIRMED | Track reversal state on the ledger entry (e.g. `reversed_at` column, checked before allowing reversal); also validate that `amount_cents` has the expected sign for the reversal direction |
| 7 | **`DEBUG = "false"` is truthy — stack traces always leaked** | `config.py:7`, `app.py:57–68` | CWE-209 | High | CONFIRMED | `DEBUG = os.environ.get("APP_DEBUG", "false").lower() in ("1", "true", "yes")` |
| 8 | **Account lockout DoS** (attacker can lock any user with 10 requests) | `routes/session.py:46–49` | CWE-307 | Medium | CONFIRMED | Also rate-limit by client IP; consider exponential backoff rather than hard lockout, or CAPTCHA |
| 9 | **Non-constant-time reset token comparison** | `password_reset.py:42` | CWE-208 | Medium | CONFIRMED | Replace `token == _derive(...)` with `hmac.compare_digest(token, _derive(...))` |
| 10 | **Weak password hashing** (custom SHA-256 chain, not memory-hard) | `auth.py:17–24` | CWE-916 | Medium | CONFIRMED | Replace with `argon2-cffi` (`argon2.PasswordHasher`) or `bcrypt` |
| 11 | **Reset token stored in plaintext in `outbox` table** | `routes/session.py:124–128` | CWE-312 | Medium | CONFIRMED | Store HMAC or hash of the token; the outbox record should not expose the usable credential |
| 12 | **Untrusted request header reflected verbatim in export response** (`X-Request-Time`) | `routes/admin.py:46` | CWE-116 | Low | CONFIRMED | Use `datetime.utcnow().isoformat()` on the server side; never reflect client-supplied headers into stored/exported data |
